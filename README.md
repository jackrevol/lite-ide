# Lite IDE

macOS·Windows용 Codex 데스크톱 워크스페이스입니다. Paseo의 프로젝트·작업 탐색 구조를 중심으로 Superset과 Orca의 작업 관리 흐름을 참고해 재구성했습니다. 참조한 코드와 구현 경계는 [설계 근거](docs/reference-design.md)에 정리했습니다.

## 주요 기능

- 프로젝트 → 작업 구조의 사이드바, 작업마다 전용 Worktree 생성, 작업명·브랜치를 한 항목으로 표시
- Git 저장소 URL로 복제 후 프로젝트 열기, 기존 로컬 폴더 열기
- Codex 한도별 남은 비율·다음 초기화 시각, 남은 초기화권·가장 먼저 만료되는 초기화권의 사용 기간
- 실제 Codex 실행, 응답 스트리밍, Markdown·코드·표 표시, 도구 실행 내용 확인
- 모델·추론 수준 선택, 실행 중단, 같은 대화 이어가기
- Codex YOLO 실행과 Codex 질문에 대한 응답
- 서브에이전트 상태·최근 활동·부모 관계 조회, 상태 필터·검색, 개별 대화·승인·추가 지시·중단
- 프로젝트·대화 기록·입력 내용의 재시작 복원, 작업 이름 변경·삭제
- 변경 파일 검색과 인라인 diff, Git에 추가하지 않은 새 파일 미리보기
- 빠른 이동(`Ctrl/Cmd K`), 새 작업(`Ctrl/Cmd N`), 변경 패널 전환(`Ctrl/Cmd Shift B`)
- 다크·라이트 테마, 960px 창에서도 유지되는 3열 배치
- 프로젝트·브랜치·빠른 이동을 한 줄에 배치한 통합 타이틀바와 네이티브 창 버튼
- 시베리안고양이 얼굴 앱 아이콘, 타이틀바 및 시작 화면 로고
- 새 버전이 있을 때 표시하는 타이틀바 업데이트 버튼, GitHub Releases 및 SHA-256 무결성 검증
- 설정(`Ctrl/Cmd ,`)에서 수동 업데이트 확인, 프로젝트별 기준 브랜치·모델·추론 기본값, 프로그램·빌드 정보 확인

## 실행

Node.js 24 이상, Git, `app-server`를 지원하는 Codex CLI가 필요합니다. 개발·실제 연결 검증은 Codex CLI 0.166.0으로 수행했습니다.

```sh
npm ci
npm run dev
```

프로젝트 추가 화면에서 Git 저장소 URL을 입력해 복제하거나 기존 로컬 폴더를 엽니다. 기본 저장 위치는 사용자 홈 아래 `Projects`이며, 폴더를 선택하지 않아도 바로 복제할 수 있습니다. 저장 위치는 필요할 때 변경할 수 있고 기본 폴더가 없으면 복제를 시작할 때 자동 생성합니다. HTTPS·SSH 주소를 지원하며 비공개 저장소는 기존 Git 인증을 사용합니다. 같은 이름의 폴더는 덮어쓰지 않습니다. 메시지를 입력한 뒤 Enter로 전송합니다. Shift Enter는 줄바꿈입니다. 설치된 Codex의 기존 로그인을 사용하며, 로그인하지 않았다면 앱의 로그인 버튼으로 연결할 수 있습니다. 모델 목록은 Codex에서 직접 조회합니다.

좌하단의 사용량은 Codex `account/rateLimits/read`에서 조회합니다. 1분 간격, 앱 복귀, 사용량 갱신 알림 및 새로고침 버튼으로 갱신하며 초기화 시각은 시스템 현지 시간으로 표시합니다. 초기화권 개수와 상세 기간은 각각 제공 여부를 구분합니다. 상세 목록에서 사용 가능하고 만료되지 않은 초기화권을 만료 시각 순으로 표시하며, 서버가 일부 상세만 제공하면 조회된 목록을 기준으로 합니다. 초기화권을 자동으로 소비하지 않습니다.

Windows에서는 npm의 `.cmd` 래퍼 대신 설치된 Codex 실행 파일을 찾아 직접 실행합니다. macOS에서는 PATH와 일반적인 사용자·Homebrew 설치 경로를 확인합니다. 렌더러는 Node.js에 접근하지 않으며 타입이 정의된 preload API를 통해 main 프로세스와 통신합니다.

상단의 빈 영역을 드래그해 창을 이동할 수 있습니다. Windows에서는 오른쪽 기본 창 버튼을 사용하며, macOS에서는 왼쪽 창 버튼을 위한 공간을 확보합니다. 검색·패널 전환 버튼은 드래그 영역에서 제외하고, 창 버튼 색상은 앱 테마와 동기화합니다.

앱을 시작한 뒤 10초 후 GitHub 최신 릴리스를 한 번만 확인합니다. 새 버전의 설치 파일이 준비되어 있을 때만 타이틀바에 **업데이트** 버튼을 표시합니다. 최신 버전이거나 조회에 실패하면 버튼을 표시하지 않으며, 다음 실행 시 다시 확인합니다. 버튼을 한 번 누르면 현재 운영체제·CPU에 맞는 설치 파일을 다운로드하고 SHA-256을 검증한 뒤 자동으로 종료·설치·재실행합니다. Windows 설치 도우미는 앱 프로세스가 종료된 것을 확인한 뒤 NSIS 설치 파일을 `/S --force-run`으로 실행합니다. macOS는 DMG에서 앱 ID·버전·코드 서명을 검증하고 새 앱을 준비한 뒤, 종료 후 기존 앱을 교체합니다. 교체 실패 시 이전 앱을 복구하며, 앱이 설치된 폴더에 쓰기 권한이 필요합니다. 다운로드 실패·취소·검증 실패 시 종료하지 않습니다. 작업이나 저장소 복제가 진행 중이면 설치를 보류하며, 작업을 마친 후 같은 버튼으로 받은 파일을 재사용해 설치할 수 있습니다. 개발 실행에서는 다운로드와 검증까지만 진행합니다.

## 저장과 실행 권한

프로젝트 이름 오른쪽 `+` 또는 `Ctrl/Cmd N`을 누르면 전용 Worktree를 생성하고 새 채팅 입력창으로 이동합니다. 다른 프로젝트의 `+`도 해당 프로젝트에서 새 Worktree를 만듭니다. 프로젝트 기본 기준 브랜치·모델·추론 수준을 적용하며, Enter로 전송하고 Shift+Enter로 줄을 바꿉니다. 옆의 **작업 설정하여 만들기** 버튼에서는 새 브랜치 이름·기준 브랜치·작업 이름·첫 요청·모델·추론 수준을 지정할 수 있습니다. **설정 → 프로젝트**에서 기본 기준 브랜치를 로컬·원격 브랜치 중 선택합니다. 원격 브랜치는 로컬에 저장된 커밋을 사용합니다. 설정의 업데이트 확인은 언제든 다시 조회하며, 확인만으로 다운로드나 설치를 실행하지 않습니다.

Codex가 서브에이전트를 생성하면 부모 작업 상단에 관리 목록이 나타납니다. 진행 중·확인 필요·종료 상태로 필터링하거나 이름·역할·작업 내용으로 검색할 수 있습니다. 사이드바에도 진행 및 확인이 필요한 서브에이전트 수가 표시됩니다. 에이전트를 선택하면 대화와 명령 출력, 승인·질문을 확인하고 개별 중단하거나 추가 지시를 보낼 수 있습니다. 실행 중 지시는 `turn/steer`로 전달하고 완료·중단 후에는 같은 대화에서 이어갑니다. 서버가 직접 입력을 지원하지 않는다고 알리거나 에이전트가 종료된 경우에는 부모 작업에서 지시해야 합니다. 활동 조회 실패는 작업 실패와 구분하며 상세 창에서 다시 조회할 수 있습니다. 실행 중인 자식이 있으면 부모 작업을 삭제할 수 없습니다. 앱 재시작 후에도 부모·자식 관계와 대화 기록을 복원하며 이전 실행은 중단 상태로 표시합니다.

프로젝트와 대화 기록은 Electron의 `appData/lite-ide` 안에 저장합니다. Worktree 작업별 입력 내용·선택한 작업·테마는 로컬 저장소에 보관합니다. 작업과 Worktree는 1:1로 연결하며 원본 프로젝트 폴더에서는 Codex를 실행하지 않습니다. 이전 로컬 작업 기록은 삭제하지 않고 복원과 목록 표시에서 제외합니다. 앱에서 새로 만든 작업만 복원하며 Git에 존재하는 다른 Worktree는 자동으로 목록에 추가하지 않습니다. 앱을 종료하면 실행 연결이 종료되며, 다시 열어 같은 작업에서 메시지를 보내 대화를 이어갈 수 있습니다.

Codex는 YOLO 모드(`danger-full-access`, 승인 정책 `never`)로 실행합니다. 새 대화와 기존 대화 재개, 각 턴에 같은 정책을 적용해 명령 실행과 파일 변경을 개별 승인 없이 진행합니다. 작업 삭제는 이 앱의 기록을 삭제하며 프로젝트 파일과 Codex 원본 세션은 삭제하지 않습니다.

## 검증

```sh
npm run typecheck
npm test
npm run build
npm run test:ui
```

UI 테스트는 격리된 임시 프로젝트와 숨겨진 Electron 창에서 실행합니다. 포커스를 가져오지 않으며, 스크린샷은 `artifacts/`에 저장합니다. Codex stdio 프로토콜 픽스처를 사용하므로 모델 사용량을 소비하지 않습니다.

실제 Codex 연결 및 계정·모델 조회:

```sh
npm run test:codex
```

실제 모델 응답 확인 및 재시작 후 대화 재개·파일 생성 검증(모델 사용량 발생):

```sh
npm run test:codex -- --live --write
```

## 패키징과 범위

`main`에 푸시하면 `.github/workflows/release.yml`이 Windows x64, macOS Apple Silicon(arm64), macOS Intel(x64)에서 테스트·빌드·패키징된 앱의 숨김 실행 검증 후 GitHub Release를 자동으로 공개합니다. 수동 실행도 `main`에서 지원합니다. 세 플랫폼이 모두 성공해야 `.exe`, 두 종류의 `.dmg`, `SHA256SUMS.txt`를 등록합니다. 추가 PAT 없이 Actions의 `GITHUB_TOKEN`을 사용합니다.

릴리스 버전은 `package.json`의 major·minor와 `기본 patch + GITHUB_RUN_NUMBER`로 생성합니다. 예를 들어 기본 `0.1.0`의 첫 실행은 `0.1.1`이고 태그는 `v0.1.1`입니다. 빌드 중의 버전 변경을 저장소에 다시 커밋하지 않으며, 같은 실행을 재시도해도 버전은 유지됩니다. 이미 공개된 릴리스는 재실행으로 덮어쓰지 않습니다. 현재 설치 파일은 개발자 인증서 서명·Apple 공증 없이 배포됩니다.

`npm run package:win` 또는 `npm run package:mac`으로 패키징합니다. 배포용 서명·공증은 별도 설정이 필요하며 macOS 실기기 검증은 수행하지 않았습니다.

현재 파일 패널은 변경 사항 검토용입니다. 범용 파일 편집기, 내장 터미널, 원격 호스트 연결은 포함하지 않습니다. Git 변경 파일은 최대 200개를 표시하고, 새 파일 미리보기는 1MB까지 지원합니다. Codex app-server는 실험적 인터페이스이므로 CLI 버전 변경 시 `test:codex`로 호환성을 확인하세요.

## UI 기반

아이콘 원본은 `resources/icon-source.png`입니다. `npm run build:icons`로 앱용 PNG, Windows ICO, macOS ICNS와 렌더러 이미지를 다시 생성합니다. Windows 아이콘에는 16~256px의 7개 크기, macOS 아이콘에는 Retina를 포함한 최대 1024px 크기가 들어 있습니다.

[coss UI](https://coss.com/ui)의 Base UI·Tailwind CSS v4 컴포넌트를 사용합니다. 기존 컴포넌트의 MIT 라이선스는 `LICENSE.coss-ui`에 포함되어 있습니다.
