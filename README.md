# Lite IDE

macOS·Windows용 Codex 터미널 워크스페이스입니다. 작업 하나가 전용 Git Worktree와 터미널을 함께 가지며, 프로젝트 탐색·터미널·변경 사항의 3열 화면으로 구성됩니다. 참조한 코드와 구현 경계는 [설계 근거](docs/reference-design.md)에 정리했습니다.

## 주요 기능

- 전용 Git 폴더·브랜치·이름·터미널 설정을 가진 단일 작업, 이름 변경·삭제 메뉴 통합
- 실제 Codex CLI 터미널과 일반 셸(PowerShell/로그인 셸), 명령 실행·키보드 단축키·복사·붙여넣기
- 입력을 PTY에 한 번만 전달하며 터미널 출력만 렌더링, 탭 전환·새로고침 시 실행과 출력 유지
- Codex 백그라운드 서버로 실행 유지, 업데이트 후 기존 세션 ID로 자동 재연결
- 드래그·키보드로 조절하고 복원하는 3열 패널, 변경 파일 검색·diff
- Git 저장소 복제와 로컬 프로젝트 열기, 프로젝트별 기준 브랜치·모델·추론 수준 기본값
- 작업 삭제 확인 한 번으로 변경 파일·추적하지 않는 파일·폴더·연결 로컬 브랜치를 함께 삭제
- 브랜치 변경을 실제 Git 정보와 동기화하고, Git 연결이 끊어진 작업은 남은 파일·브랜치를 보존하며 로컬 기록만 정리
- Codex 사용량, 다크·라이트 테마, 빠른 이동, 통합 타이틀바, GitHub Releases 업데이트

## 실행

Node.js 24 이상, Git, Codex CLI 0.166.0 이상이 필요합니다. 개발·실제 연결 검증은 Codex CLI 0.166.0으로 수행했습니다.

```sh
npm ci
npm run dev
```

프로젝트 추가 화면에서 Git 저장소 URL을 입력해 복제하거나 기존 로컬 폴더를 엽니다. 기본 저장 위치는 사용자 홈 아래 `Projects`이며, 폴더를 선택하지 않아도 바로 복제할 수 있습니다. 저장 위치는 필요할 때 변경할 수 있고 기본 폴더가 없으면 복제를 시작할 때 자동 생성합니다. HTTPS·SSH 주소를 지원하며 비공개 저장소는 기존 Git 인증을 사용합니다. 같은 이름의 폴더는 덮어쓰지 않습니다. 새 작업을 만들면 설치된 Codex CLI가 작업 폴더에서 실행됩니다. 명령 메뉴와 입력 편집·이력·중단은 Codex CLI가 직접 처리합니다. Codex는 전체 화면 모드로 실행해 입력창을 하단에 유지합니다. Enter는 전송, Shift+Enter는 줄바꿈, Ctrl+Enter는 명령 대기열로 전달합니다. `/`로 사용 가능한 명령을 확인하고 `!`로 셸 명령을 실행할 수 있습니다. 상단의 **셸**을 선택하면 같은 작업 폴더에서 일반 명령을 실행합니다. 모드를 전환하면 현재 프로세스가 종료됩니다. 설치된 Codex의 기존 로그인과 설정을 사용하며, 로그인도 Codex 터미널에서 진행합니다.

좌하단의 사용량은 Codex `account/rateLimits/read`에서 조회합니다. 1분 간격, 앱 복귀, 사용량 갱신 알림 및 새로고침 버튼으로 갱신하며 초기화 시각은 시스템 현지 시간으로 표시합니다. 초기화권 개수와 상세 기간은 각각 제공 여부를 구분합니다. 상세 목록에서 사용 가능하고 만료되지 않은 초기화권을 만료 시각 순으로 표시하며, 서버가 일부 상세만 제공하면 조회된 목록을 기준으로 합니다. 초기화권을 자동으로 소비하지 않습니다.

Windows에서는 npm의 `.cmd` 래퍼 대신 설치된 Codex 실행 파일을 찾아 직접 실행합니다. macOS에서는 PATH와 일반적인 사용자·Homebrew 설치 경로를 확인합니다. 렌더러는 Node.js에 접근하지 않으며 타입이 정의된 preload API를 통해 main 프로세스와 통신합니다.

상단의 빈 영역을 드래그해 창을 이동할 수 있습니다. Windows에서는 오른쪽 기본 창 버튼을 사용하며, macOS에서는 왼쪽 창 버튼을 위한 공간을 확보합니다. 검색·패널 전환 버튼은 드래그 영역에서 제외하고, 창 버튼 색상은 앱 테마와 동기화합니다.

앱을 시작한 뒤 10초 후 GitHub 최신 릴리스를 한 번만 확인합니다. 새 버전의 설치 파일이 준비되어 있을 때만 타이틀바에 **업데이트** 버튼을 표시합니다. 최신 버전이거나 조회에 실패하면 버튼을 표시하지 않으며, 다음 실행 시 다시 확인합니다. 버튼을 한 번 누르면 현재 운영체제·CPU에 맞는 설치 파일을 다운로드하고 SHA-256을 검증한 뒤 자동으로 종료·설치·재실행합니다. Windows 설치 도우미는 앱 프로세스가 종료된 것을 확인한 뒤 NSIS 설치 파일을 `/S --force-run`으로 실행합니다. macOS는 DMG에서 앱 ID·버전·코드 서명을 검증하고 새 앱을 준비한 뒤, 종료 후 기존 앱을 교체합니다. 교체 실패 시 이전 앱을 복구하며, 앱이 설치된 폴더에 쓰기 권한이 필요합니다. 다운로드 실패·취소·검증 실패 시 종료하지 않습니다. Codex 세션이나 터미널이 열려 있어도 설치할 수 있습니다. 설치 전에 실행 중인 터미널 목록과 연결 정보를 저장하며, 재실행 후 선택하지 않은 작업까지 자동으로 다시 연결합니다. Codex 작업은 공유 백그라운드 서버에서 계속 실행되며, 첫 요청을 다시 보내지 않고 저장된 세션 ID로 연결합니다. 저장소 복제 중에만 설치를 보류하며, 복제를 마친 후 같은 버튼으로 받은 파일을 재사용합니다. 개발 실행에서는 다운로드와 검증까지만 진행합니다.

타이틀바 아래 3열 패널은 경계선을 드래그하거나 키보드 방향키로 크기를 조절할 수 있습니다. 조절한 크기는 다시 실행해도 유지되며 변경 패널을 숨긴 상태의 배치도 별도로 저장합니다. 가운데 작업 탭을 전환해도 실행 중인 터미널은 유지됩니다. 사이드바 각 작업의 `⋯` 메뉴에서 이름 변경·삭제를 실행합니다.

## 저장과 실행 권한

프로젝트 이름 오른쪽의 브랜치 아이콘을 누르면 해당 프로젝트의 **기본 기준 브랜치** 설정을 바로 엽니다. 새 작업 창의 **기본 기준 브랜치 관리**에서도 같은 설정을 열 수 있으며, 설정을 닫으면 작성 중인 작업 입력으로 돌아옵니다. 로컬·원격 브랜치는 목록에서 구분해서 표시합니다. 외부에서 브랜치를 추가하거나 삭제했다면 **브랜치 목록 새로고침**으로 다시 읽습니다. 이 버튼은 fetch를 실행하지 않습니다. 저장된 기준 브랜치가 사라지면 다른 브랜치를 선택해야 저장하거나 새 작업을 만들 수 있습니다.

프로젝트 이름 오른쪽 `+`, 작업 탭의 `+` 또는 `Ctrl/Cmd N`을 누르면 작업 생성 창을 엽니다. 프로젝트 기본 기준 브랜치·모델·추론 수준을 불러오며, 새 브랜치 이름·기준 브랜치·작업 이름·첫 요청·모델·추론 수준을 확인하거나 변경한 뒤 **만들기** 또는 **만들고 시작**을 눌러 작업 전용 Git 폴더와 브랜치를 생성합니다. 작업 이름을 비워 두면 브랜치 이름을 표시합니다. 취소하면 작업이나 Worktree를 만들지 않습니다. 다른 프로젝트의 `+`도 해당 프로젝트의 작업 생성 창을 엽니다. **설정 → 프로젝트 → 기본 기준 브랜치**에서 로컬·원격 브랜치 중 기본값을 선택하고 저장합니다. 원격 브랜치는 마지막으로 가져온 상태를 사용하며, 기본값은 다음 작업부터 적용됩니다.

프로젝트와 Codex 실행 이력은 Electron의 `appData/lite-ide`에 저장됩니다. 작업 목록은 `lite-ide.workspace.v3`에 객체 하나씩 저장하며, 이전 작업과 Worktree 별칭은 하나의 이름으로 이전합니다. 이전 화면에서 작성 중인 입력은 자동 실행하지 않고 **입력 가져오기**로 터미널에 붙여넣을 수 있습니다. 앱을 종료하면 터미널 화면의 연결만 종료되며 Codex 작업은 공유 백그라운드 서버에 유지됩니다. Codex를 다시 열면 저장된 세션 ID로 같은 대화에 연결합니다. 업데이트 후에는 이전에 실행 중이던 작업의 터미널을 자동으로 엽니다. 일반 셸은 같은 작업 폴더에서 새 프로세스로 시작하므로 실행 중이던 셸 명령과 환경 변수는 복원하지 않습니다.

**작업 삭제**를 선택하면 변경 파일 수와 삭제 범위를 확인하는 창이 한 번 표시됩니다. **변경 사항 포함 삭제**를 누르면 터미널을 종료하고 수정·추적하지 않는 파일, 무시된 파일, 작업 폴더와 연결된 로컬 브랜치를 함께 삭제합니다. 취소하면 파일과 터미널은 유지됩니다. 원본 프로젝트·별도로 열린 프로젝트·잠긴 Worktree는 삭제하지 않으며 Codex 원본 세션과 원격 브랜치는 유지합니다.

Codex는 기존과 같이 YOLO 모드(`--dangerously-bypass-approvals-and-sandbox`)로 실행합니다. 터미널 입력은 타입이 정의된 preload API를 통해 main의 PTY로 전달하며 렌더러는 Node.js를 직접 사용하지 않습니다. Windows는 ConPTY, macOS는 PTY를 사용하고 배포 시 `node-pty` 네이티브 파일을 ASAR 밖에 포함합니다.

## 검증

```sh
npm run typecheck
npm test
npm run build
npm run test:ui
```

UI 테스트는 격리된 임시 프로젝트와 숨겨진 Electron 창에서 실행합니다. 포커스를 가져오지 않으며, 스크린샷은 `artifacts/`에 저장합니다. Codex 계정 조회와 터미널 픽스처 및 실제 셸을 사용하므로 모델 사용량을 소비하지 않습니다. 터미널 입력·재연결의 중복 출력, Ctrl+C, 단일 작업 이름·삭제, 변경 사항 1회 확인 삭제, 재시작 복원과 패널 조절을 검증합니다.

실제 Codex 연결 및 계정·모델 조회:

```sh
npm run test:codex
```

실제 모델 응답 확인 및 재시작 후 대화 재개·파일 생성 검증(모델 사용량 발생):

```sh
npm run test:codex -- --live --write
```

실행 중인 Codex 작업을 앱 재시작 중에도 유지하고, 같은 세션·턴의 완료와 터미널 자동 연결을 검증합니다(모델 사용량 발생):

```sh
npm run test:codex -- --terminal
```

## 패키징과 범위

`main`에 푸시하면 `.github/workflows/release.yml`이 Windows x64, macOS Apple Silicon(arm64), macOS Intel(x64)에서 빌드·패키징 후 GitHub Release를 자동으로 공개합니다. Actions에서는 테스트를 실행하지 않으며 위 검증 명령은 로컬에서 실행합니다. 수동 실행도 `main`에서 지원합니다. 세 플랫폼이 모두 성공해야 `.exe`, 두 종류의 `.dmg`, `SHA256SUMS.txt`를 등록합니다. 추가 PAT 없이 Actions의 `GITHUB_TOKEN`을 사용합니다.

macOS 터미널의 `node-pty@1.1.0` 실행 권한 문제는 설치 후와 패키징 후(서명 전)에 `scripts/prepare-pty.cjs`로 보정합니다. 관련 upstream 이슈: https://github.com/microsoft/node-pty/issues/919.

패키징은 `node-pty`에 포함된 Node-API 사전 빌드 바이너리를 사용해 C++ 재컴파일을 생략합니다. 패키징 후 대상 플랫폼·아키텍처의 필수 바이너리를 확인하고, 소스와 빌드용 파일은 배포에서 제외합니다. 렌더러 전용 라이브러리는 Vite 번들에 포함되므로 `devDependencies`로 관리해 중복 복사를 줄입니다. Actions는 운영체제·아키텍처별로 Electron과 패키징 도구 다운로드를 캐시합니다. 자체 업데이트는 전체 설치 파일과 SHA-256을 사용하므로 DMG 차등 업데이트용 blockmap은 생성하지 않습니다.

릴리스 버전은 `package.json`의 major·minor와 `기본 patch + GITHUB_RUN_NUMBER`로 생성합니다. 예를 들어 기본 `0.1.0`의 첫 실행은 `0.1.1`이고 태그는 `v0.1.1`입니다. 빌드 중의 버전 변경을 저장소에 다시 커밋하지 않으며, 같은 실행을 재시도해도 버전은 유지됩니다. 이미 공개된 릴리스는 재실행으로 덮어쓰지 않습니다. 현재 설치 파일은 개발자 인증서 서명·Apple 공증 없이 배포됩니다.

`npm run package:win` 또는 `npm run package:mac`으로 패키징합니다. 배포용 서명·공증은 별도 설정이 필요하며 macOS 실기기 검증은 수행하지 않았습니다.

로컬에서 `node scripts/check-packaged.mjs win x64` 또는 `node scripts/check-packaged.mjs mac arm64`로 패키징된 앱의 숨김 실행·버전·실제 PTY 명령 실행을 확인할 수 있습니다. 이 검증은 Actions에 추가하지 않습니다.

현재 파일 패널은 변경 사항 검토용입니다. 범용 파일 편집기, 내장 터미널, 원격 호스트 연결은 포함하지 않습니다. Git 변경 파일은 최대 200개를 표시하고, 새 파일 미리보기는 1MB까지 지원합니다. Codex app-server는 실험적 인터페이스이므로 CLI 버전 변경 시 `test:codex`로 호환성을 확인하세요.

## UI 기반

아이콘 원본은 `resources/icon-source.png`입니다. `npm run build:icons`로 앱용 PNG, Windows ICO, macOS ICNS와 렌더러 이미지를 다시 생성합니다. Windows 아이콘에는 16~256px의 7개 크기, macOS 아이콘에는 Retina를 포함한 최대 1024px 크기가 들어 있습니다.

[coss UI](https://coss.com/ui)의 Base UI·Tailwind CSS v4 컴포넌트를 사용합니다. 기존 컴포넌트의 MIT 라이선스는 `LICENSE.coss-ui`에 포함되어 있습니다.
